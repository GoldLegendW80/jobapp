Refs #343 and #563. Implements SPEC-apply's owner decision of 2026-10-19.

Only a known adapter's form_changed fill error may start generic filling. It keeps the same
page, lease, tools, profile context and person answers, and starts at most once per attempt.
Known filled values are retained only for the same field structure and refilled by code.
Recorded earlier wizard steps and their outcomes remain part of the approved replay record.
Payment, captcha, sign in, e-mail code and LinkedIn checks still precede generic model work.

The code-owned designated:strategy row holds version 1, vendor, original form_url and replay
target. It has source identity and kind designated. Model tools accept refs only. The normal
person edit route refuses every designated key, and the fill never accepts such a key from
an ordinary field outcome. Composite ownership and the canonical answers/documents hash bind
this row without copying owner IDs or document version payloads into its JSON value.
The central approval serializer omits the row. Queue output only counts required Left rows.

The submit lease selects generic only from this exact saved strategy and the known hosted
form target. It never starts a model or a fallback on a submit readback failure. It replays
approved steps and values, verifies field structures and designation, and preserves A6's
fresh readback, hash, document, clock, approval, kill switch and host locks before the click.

A valid saved known-ATS binding is the only exception to Full auto's agent_designated
refusal. FULL_AUTO_SOURCES is unchanged. Every other Full auto and model-check refusal stays.
Unknown-site generic filling remains Review first only. Unrecognised widgets are not ignored.

Budget interpretation: fallback shares the known attempt's 34,000 token allowance, subtracting
all previous answer-agent input and output. A reported token limit leaves zero allowance.
The generic agent retains its existing 30-turn per-agent cap; the answer agent's three turns
remain that agent's cap. The original form deadline starts before the known fill, the runtime
preserves it, and the fallback runs under its remaining wall window. Its original lease is
never reacquired or extended, so the browser's unchanged active and wait clocks still govern.
No model, turn, token, active, wait, resource or configured timeout limit has been raised.
